# Временный SSH-доступ для агентов

1. Подключайся к серверу только для явно порученной владельцем задачи. Имя хоста/IP, SSH-пользователя и способ доступа получай от владельца; не записывай их в репозиторий.
2. Используй отдельный временный SSH-ключ. Храни приватный ключ вне репозитория с правами `600`; владельцу передавай только `.pub`. Не проси и не копируй приватный ключ владельца.
3. Добавление временной публичной строки в `authorized_keys` и проверку fingerprint сервера согласуй с владельцем. Не отключай проверку host key.
4. Подключайся выданным пользователем и используй `sudo` только для необходимых операций. Не выводи и не сохраняй production `.env`, пароли, токены или почтовые credentials.
5. Пока задача продолжается, сохраняй доступ. Не удаляй и не отключай временный SSH-ключ по собственной инициативе. После окончания работ сначала согласуй отзыв с владельцем; затем удаляй только свою строку по уникальному комментарию, никогда не перезаписывай весь `authorized_keys`.
6. В Git не добавляй приватные ключи, серверные адреса, пароли, токены или production-конфигурацию.
